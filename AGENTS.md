## New Architecture is not configurable here — do not add the flag

There is **no** `newArchEnabled` key in `app.json`, and none should be added. On SDK 57 / RN 0.86 the New
Architecture is unconditional; the string `newArchEnabled` exists in the installed tree only as an internal
parameter at `node_modules/expo/ios/AppDelegates/ExpoReactNativeFactory.swift:85`, and `react-native/Libraries`
contains no legacy-architecture code. If a guide, blog post, or your own memory says to set
`expo.newArchEnabled: true`, ignore it — it is dead config here.

## Generated files that will bite you

`expo-env.d.ts` is **gitignored and generated by `expo start`** (written from
`@expo/cli/.../type-generation/expo-env.js`). It is what pulls in `expo/types`, which declares
`*.module.css`. Consequences:

- On a fresh clone, `npx tsc --noEmit` fails with `TS2307: Cannot find module '*.module.css'` and
  `TS2882: ... side-effect import of '@/global.css'`. **This is a known false failure, not a real bug.**
  Fix by running `npx expo start` once, or by writing the file yourself with exactly:
  ```ts
  /// <reference types="expo/types" />

  // NOTE: This file should not be edited and should be in your git ignore
  ```
- Do **not** commit it, and do **not** add CSS-module type declarations to `tsconfig.json` or a hand-rolled
  `.d.ts` to work around this — that duplicates Expo's own declarations.
- `.expo/types/**/*.ts` is also generated (typed routes); same story.

## TypeScript gotchas in this codebase

- `ColorSchemeName` is `'light' | 'dark' | 'unspecified'` — it is **not** nullable. But
  `Appearance.getColorScheme()` returns `ColorSchemeName | null | undefined`, so it must be coalesced
  (to `'unspecified'`, not `null`) to typecheck.
- `Appearance.addChangeListener` returns a subscription with `.remove()`; do not call the result as a
  bare function.
- For any value that differs between server and client (web static rendering), use
  `useSyncExternalStore` with a `getServerSnapshot`. Do **not** use the `useState` + `useEffect`
  hydration-flag pattern — it is banned by the active lint rules (see below).
- `tsconfig.json` has `strict: true`. Keep it that way; do not loosen compiler options to make an error go away.

## Lint rules that actually fail the build

`eslint.config.js` (flat config, generated by `npx expo lint`) extends `eslint-config-expo/flat`, which
includes the React Compiler rules. `react-hooks/set-state-in-effect` is an **error**: calling `setState`
synchronously in an effect body fails `npx expo lint`. Prefer `useSyncExternalStore`, event handlers, or
derived values. `npx expo lint` auto-installs `eslint` + `eslint-config-expo` on first run and prints a
`Cannot find module 'eslint'` error in that same run — re-run it and it passes.

## Ask before running dependency commands

The user runs `npm install` and other package-manager commands themselves. Do not run `npm install`,
`npm i`, or anything that mutates `node_modules` or the lockfile unless explicitly asked. Do run
`npx expo install <pkg>` (or `npx expo-doctor`, `npx expo lint`, `npx tsc --noEmit`) when the task needs it,
and hand the user a copy-pasteable command block otherwise.

`npm install` on this project has timed out (`ETIMEDOUT`) on a cold cache. If the user hits it, the working
retry is:

```bash
npm install --fetch-retries=5 --fetch-retry-maxtimeout=120000
```

## Verification gate

Run all four before declaring a task done. A clean baseline at the time of writing:

```bash
npx tsc --noEmit      # must be silent
npx expo lint         # must be silent
npx expo install --check   # expect: Dependencies are up to date
npx expo-doctor       # expect: 21/21 checks passed
```

Note `npx expo-doctor` installs its own package on first use; it is safe to run. `npx expo config --type public`
prints non-JSON, so add `--json` before piping into a parser.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

Prefer appending `.md` to any `docs.expo.dev` URL to get the Markdown version intended for agents.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present). This project currently uses **npm**
(`package-lock.json`), not bun.

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server (also generates expo-env.d.ts)
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
npx expo install --check    # check for version mismatches (no writes)
npx expo install --fix      # fix incompatible package versions
```

Run lint and typecheck before declaring any task done.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- The scaffold ships native tabs (`expo-router/unstable-native-tabs` era API — confirm against SDK 57 docs) plus platform-split web variants like `app-tabs.tsx` / `app-tabs.web.tsx`.
- Docs: https://docs.expo.dev/router/introduction.md

## Styling and assets

- Web styling uses CSS: `src/global.css` for resets/variables, `*.module.css` alongside components. Native styling stays in `StyleSheet` / props.
- Use `expo-image` for all images (caching, blur, transitions) rather than React Native's `Image`.
- Icons: `expo-symbols` (SF Symbols, iOS) is already installed.

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `bunx eas-cli <command>` in Bun projects, or `npx eas-cli@latest <command>` otherwise; substitute that for bare `eas` in docs examples.
There is no `eas.json` in the repo yet and `eas-cli` is not installed — add them when the project first needs a cloud build.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
- Never put API keys or tokens in committed files. Use `EXPO_PUBLIC_*` env vars for public config and `eas secret` / EAS environment variables for anything sensitive.
